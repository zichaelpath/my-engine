# Devlog 046 — CI: A Second Machine That Never Forgets

## Goal

Arc 1's third lesson: make Lesson 45's harness run *by itself*. A GitHub Actions workflow that builds the whole engine on Linux **and** Windows for every push to `main`, and runs MyTests on both — so "it works on my machine" stops being the engine's quality bar, on either side of the OS line.

## Concept

- **Why CI, why now.** Phase 1's two real defects both escaped local verification: the flip bug needed a *player*, and the khrplatform break needed a *different operating system*. Lesson 45 gave the engine checks; this lesson gives the checks a machine that runs them on every change, on both platforms, from a clean checkout — the exact conditions that caught us out. Zac's Windows build error (Lesson 44) is now a job that runs before he ever pulls.
- **The workflow mirrors the documented builds.** Linux: the system packages the build actually needs, plain `cmake -B BuildLinux` (no rig-specific paths — a clean runner has no `devdeps`, and must not need one), full build, then the harness under `xvfb-run` (Lesson 45's finding: the engine core owns GL resources, so the suite runs under a virtual display *by design*). Windows: `docs/WINDOWS_BUILD.md` automated — configure, `--config Release` build, `MyTests.exe`.
- **A green checkmark must mean the checks ran.** The harness exits 0 even when the whole suite SKIPs (that honesty is for humans). A pipeline step that pipes through `tee` would mask the exit code anyway — so the Linux test step greps the log for `0 failed` **and** a non-zero passed count. A wholesale skip cannot pass as green.
- **Private repo, real CI.** The runs execute on GitHub's runners against the private repository; the run page and logs are the lesson's evidence, read back through `gh` rather than assumed.

## Code built

- `.github/workflows/build.yml` — two jobs (`linux`, `windows`) on push/PR to `main`. `actions/checkout@v5` (bumped from v4 in the closing commit to clear GitHub's Node 20 deprecation annotation).

## What broke

Nothing — and that is reported with the suspicion it deserves. Both jobs went green on the **first** run, which usually means the test isn't testing anything; here the logs were read to prove otherwise: both jobs' test steps show the harness's own `RESULT: 10 passed, 0 failed, 0 skipped` — the full suite, including the render check, executing on a clean Ubuntu runner *and* a clean Windows runner (the Windows runner's GL stack runs the flipped-sprite measurement for real, no skip). The one annotation on the run was GitHub's Node 20 deprecation notice for checkout@v4, fixed by the v5 bump in this lesson's closing commit — whose own push re-ran the workflow green.
